# 吃史仙人（aemeath_chishi）说明

> AstrBot 插件，移植自 Electron 版 [chishi-xianren](https://github.com/Alphamancer/chishi-xianren) v1.0.4。
> 作用：群里有人发**合并转发 / 分享卡片 / 聊天截图**，她自动读完评一句；内容够「史」（或命中强制标签）就静默搬到指定群，也支持你手动叫她搬。
> 代码：`astrbot/plugins/astrbot_plugin_aemeath_chishi/`（main.py / metadata.yaml / _conf_schema.json）

---

## 一、为什么是「移植」而不是安装

原插件是给 **Electron 版 QQ Agent** 写的 JS 插件（`plugin.json` + `api.registerTool`），AstrBot 是 Python 宿主，两套框架互不兼容，无法直接安装，所以按它的行为重写。

移植时踩到的两个硬限制：

| 限制 | 处理 |
|---|---|
| AstrBot 4.29.1 原生**丢弃合并转发消息段**（日志报"不支持的消息段类型，已忽略"） | 插件绕过适配器，直接解析原始 OneBot 事件（`event.message_obj.raw_message`），并用协议端 `get_forward_msg` 拉取内容 |
| 服务器没有 OCR，原版靠本地 OCR 读截图 | 实测当前模型 deepseek-flash **支持看图**，直接把图片 URL 传给模型（`text_chat(image_urls=...)`），不需要 OCR |

## 二、消息流

### 1. 吃到什么

| 类型 | 说明 |
|---|---|
| 合并转发 | 原始事件里的 `forward` 段，用 `get_forward_msg` 拉取节点内容 |
| 分享卡片 | `json` / `xml` 段，提取标题+摘要 |
| 聊天截图（纯图片） | 默认**不吃**（`eatImages=false`），避免表情包刷屏；开启后只处理「不带文字的纯图片」 |
| 引用消息 | 你引用一条转发再说「搬过去」时，用 `get_msg` 解析被引用消息（含内层转发） |
| 二级转发（套娃） | 内联 `content` 直接解析，见下文 |

### 2. 读取细节

- 转发节点逐条解析：发送者昵称、QQ、文本、图片
- 图片保留真实 URL，搬运时塞回节点（AstrBot 会自动转 base64，不怕链接过期）
- 二级转发（套娃）：
  - 内层 `content` 实测是**消息对象数组**（`{"sender":{...},"message":[...]}`），另外兼容 node 数组与裸消息段数组
  - 内层转发整段只有它 → 还原成**嵌套卡片**（点开可逐层查看）
  - 和别的消息混排 → 摊成 `[内层转发]…[内层转发完]` 文字（直接传转发段会变成 XML 卡片）
  - 按 id 拉内层转发会被 NapCat 拒绝（`retcode=1200 消息已过期或者为内层消息`），所以只吃内联内容
  - 深度上限 2 层；仍取不到时记日志并用「[内层转发未展开]」占位

### 3. 评价

- 人设：默认读取 `astrbot_plugin_aemeath_persona` 的 `SYSTEM_PROMPT`，也可在配置里单独指定 `persona`
- 模型输出固定三行：

```
TAG: 美少女,抽象,擦边,R18|其他
LV: <1-5 的数字>
<一句反应，不超过 summaryChars 字>
```

- 等级：1 白开水 / 2 有点意思 / 3 逆天 / 4 典中典 / 5 破防
- 评语**永远发**（除非模型没返回），过滤只影响「搬不搬」

## 三、搬运判断（自动搬）

按顺序执行，越靠前优先级越高：

```
1. R18 拦截：TAG 含 R18（feedSkipTags）或文本命中 feedSkipKeywords → 绝不搬
2. 指定群只搬抽象：来源群在 `abstractOnlyGroups` 里 → 只有 TAG 命中「抽象」才搬，其他标签一律不搬
3. B站内容专用：链接是 bilibili.com / b23.tv，或卡片标题含哔哩哔哩
   → **默认不自动搬**（biliAutoFeed=false），只在你手动「这条也搬」时才发；打开 biliAutoFeed 后才走正常的标签/等级规则
4. 强制搬运：TAG 命中 feedForceTags（默认 美少女,抽象,擦边）→ 直接搬
            或文本命中 feedForceKeywords
5. 黑名单：来源群 / 发送者在 feedBlockList → 不搬
6. 常规搬运：LV ≥ feedMinLevel（默认 3）且 random < feedProbability（默认 0.3）→ 搬
7. 去处：feedGroups 非空，自动排除来源群
8. 配额：同来源群每小时最多 feedMaxPerHour 份
9. 去重：
   - **内容级（跨群）**：按「正文 + 节点文本 + 图片 URL + 卡片链接」算指纹，`dupWindowMinutes`（默认 60 分钟）内同一份内容只搬一次——同一个人在 A、B 两个群各发一遍，目标群只会收到一份；`0` 关闭
   - **消息级**：同一份内容（消息 id）在 `dedupeMinutes` 内不重复搬（跨目标群分别计数，防止重复发送失败重试）
```

### 标签体系

| 标签 | 判定 | 结果 |
|---|---|---|
| `美少女` | 二次元美图 / 动漫少女 / 换脸图 | 强制搬 |
| `抽象` | 抽象话、离谱整活、烂梗、逆天截图 | 强制搬 |
| `擦边` | 轻度性感、暗示、露而不露 | 强制搬 |
| `R18` | 色情、露骨性暗示 | 绝不搬（最高优先级） |
| `其他` | 都不沾 | 走常规 Lv + 概率 |

- **擦边与 R18 互斥**（提示词要求只选一个）；万一同时出现，R18 优先
- 每条被吃的内容都会记日志：`[aemeath_chishi] 内容判定：标签=... 等级=...`

### 搬运形式

- 有转发节点 → 重建**合并转发卡片**（`Comp.Node` / `Comp.Nodes`，群聊 `send_group_forward_msg`、私聊 `send_private_forward_msg`）；节点内图片随节点携带；二级转发还原成嵌套节点
- 没有节点（卡片/纯图）→ 发 `【搬史】+ 文字 + 图片`；**分享卡片附带原始链接**（从 json 的 `jumpUrl`/`qqdocurl`/`url` 或 xml 的 `url=` 提取，B站视频可直接点开）
- 转发发送失败 → 自动回退文字+图片，不丢内容

## 四、手动搬运指令

| 指令 | 作用 |
|---|---|
| `搬过去` / `转过去` / `喂一下` / `搬给我` 等 | 搬到 `feedGroups` 的第一个群（排除来源群） |
| `这条也搬` / `这个也搬` / `再搬一次` / `这图搬走` | 同上的口语说法：把最近一份内容搬到 `feedGroups`（否定说法如「这条别搬」不会触发） |
| `发我` | 搬到 `feedPrivateTarget` 的私聊 |
| `发给12345678` / `私聊12345678` | 搬到那个人的私聊 |
| `搬到859027267` / `搬到…` / `搬给…` / `转给…` / `喂给…` / `群859027267` | 搬到那个群 |
| 只发一串群号/QQ号 | 按位数判断群或私聊 |

规则：

- 指令只认**短消息**（≤24 字），避免普通聊天里带「发给/转到」被误判
- 群里只有 `ownerQQ` 能叫搬；私聊不限
- 支持 **@机器人** 发送（@ + 普通聊天仍走正常对话）
- 支持**引用一条转发**后说指令
- 手动搬**不受**等级/概率/黑名单/R18/主题标签限制（R18 只拦自动搬）

## 五、配置项

| 配置 | 默认 | 线上值 | 说明 |
|---|---|---|---|
| `enabled` | true | true | 总开关 |
| `watchGroups` | 空 | 空 | 在哪些群主动吃（空=所有群） |
| `commentGroups` | 空 | 空 | 在哪些群开口评价（空=所有群） |
| `feedGroups` | 空 | `900000001,900000006,900000003,900000002` | 自动搬去哪里 |
| `feedPrivateTarget` | 空 | `<ADMIN_QQ>` | 「发我」搬给谁 |
| `feedBlockList` | 空 | `900000007,900000005` | 不自动搬的群/QQ |
| `feedForceTags` | `美少女,抽象,擦边` | 同默认 | 强制搬运的主题标签 |
| `feedForceKeywords` | 空 | 空 | 强制搬运的关键词 |
| `feedSkipTags` | `R18` | `R18` | 禁止搬运的主题标签（最高优先级） |
| `biliAutoFeed` | `false` | `false` | B站卡片是否自动搬史；关闭时只允许手动搬 |
| `abstractOnlyGroups` | 空 | `900000009` | 这些群作为来源时只搬「抽象」标签的内容 |
| `feedSkipKeywords` | 空 | 空 | 禁止搬运的关键词 |
| `commentEnabled` | true | true | 吃完要不要说话（关掉则连自动搬也不执行） |
| `eatImages` | false | false | 是否吃纯图片/截图 |
| `feedProbability` | 0.3 | 0.3 | 常规搬运概率 |
| `feedMinLevel` | 3 | 3 | 常规搬运等级门槛 |
| `feedMaxPerHour` | 20 | 20 | 每小时自动搬上限（按来源群计） |
| `dedupeMinutes` | 5 | 5 | 同一内容（消息 id）去重窗口 |
| `dupWindowMinutes` | 60 | 60 | **跨群内容去重窗口**（同内容在多个群出现时只搬一次；0=关闭） |
| `summaryChars` | 40 | 40 | 评语字数上限 |
| `maxChars` | 60000 | 60000 | 每轮读取字数上限 |
| `maxImages` | 6 | 6 | 每轮送模型的最大图片数 |
| `ownerQQ` | 空 | `<ADMIN_QQ>` | 群里唯一能叫搬的人 |
| `persona` | 空 | 空 | 评语人设（空=自动读人设插件） |

## 六、已知限制

1. 二级转发只能吃**内联内容**；NapCat 对二级 id 返回 1200，取不到就显示「[内层转发未展开]」
2. 深度上限 2 层（更深的记录不展开）
3. 纯图片默认不吃；开启 `eatImages` 后仍会跳过图文混排的消息
4. 评语必发——没有「静默吃」模式（如需再加）
5. 自动搬上限按**份数**计（每份内容算一次），不是按目标群数
6. 手动搬不看主题标签/R18，由你自己把关
7. 卡片图标/表情包等媒体不会被当「史」处理

## 七、测试与部署

- 桩测试：`python astrbot/tests/test_plugins.py`，共 **142** 项（吃史相关覆盖：转发/卡片/图片解析、分级解析、标签解析、搬运指令与黑名单、强制搬运（美少女/抽象/擦边）、R18 拦截、合并转发重建、二级转发（node 数组/段数组/消息对象）、@机器人+引用转发、去重与配额）

- 线上路径：`/opt/astrbot/plugins/astrbot_plugin_aemeath_chishi/`，配置 `/opt/astrbot/data/config/astrbot_plugin_aemeath_chishi_config.json`
- 日志：`docker logs astrbot | grep aemeath_chishi`，关键行：
  - `转发段类型: [...]`（每轮拉取）
  - `内容判定：标签=... 等级=...`（每次评价）
  - `主题标签「...」强制搬` / `命中禁止搬运「R18」，不搬` / `命中硬性关键词`
